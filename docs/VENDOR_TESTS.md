# Vendored module tests

What each vendored module's own testbench did before it was wired to anything, and where a
substitute was necessary. `docs/WORKFLOW.md` requires the upstream bench to run **unchanged**
first; this file records the cases where upstream's bench does not run at all, because that is a
finding about the copy, not a licence to skip the proof.

Reproduce with the commands named here. Every vendor copy is byte-exact (`-text`,
`PROVENANCE.md` per directory).

---

## jt51 (YM2151) - **PASS**, derived bench

`rtl/sound/jt51/` is jotego's `hdl/` at `985a573`, taken via `Arcade-Silkroad_MiSTer`. Upstream's
conformance bench is `ver/jt51_con` (stimuli generator + C++ harness) plus `ver/common`, and it
**cannot run at that commit**:

| problem | evidence |
|---|---|
| `ver/common/jt51_test.vh` does not parse | missing comma after `.xright (xright)`, before `.sample (sample)` |
| the file list is stale | `ver/common/basic.f` names `jt51_lfo_lfsr.v` and `jt51_csr_ch.v`; the RTL has `jt51_noise_lfsr.v` and `jt51_reg_ch.v` |
| the C++ harness does not match the RTL | `ver/jt51_con/obj_dir/jt51_con.cc` drives `d_in`/`d_out`, renamed to `din`/`dout`; it also lacks `using namespace std` |
| Verilator 5.050 rejects the bench config | `ver/jt51_con/config.vlt` uses `lint_off -msg NAME`; 5.x wants `lint_off -rule NAME -file "*"` |
| the C++ objects do not link here | `verilated.o` and the harness disagree on the libstdc++ string ABI under MSYS2 g++ 16.2 |

The C++ harness is also the only part that dumps samples: the iverilog path produces no sample
stream at all. So "unchanged" is not available at any Verilator or iverilog version.

**Substitute.** `sim/jt51_tb/tb_jt51.sv` is upstream's stimulus/replay logic (`jt51_test.vh`) with
the comma fixed, the stale file list replaced by the actual RTL, and the C++ harness's sample dump
written in Verilog. `sim/jt51_tb/inputs.vh` is generated by upstream's `inputs` tool, unchanged,
with the bench's default configuration (CON 7, OPMASK 1, TL 0, FL 0, CH 0). The reference is
upstream's own `bin/print_con`, which prints the OPM model's output for the same configuration -
the same comparison the upstream `go` script makes with `sdiff`.

```
scripts/sim_jt51.sh
PASS: 4462 samples match the OPM reference
```

4462 is every sample the bench emits after the tone is programmed, within the 80 ms window
upstream's `jt51_test.v` allows. Leading zeros before the tone starts are dropped, which is the
filter the C++ harness applied; a non-zero value there would still fail.

**Coverage note.** `ver/jt51_con/test_all` sweeps CON 0-7, FL 0-7, OPMASK 15-16, TL 0-3 - 256
runs. Only the bench's default (CON 7) ran here. Phase 4 runs the sweep when the chip is wired to
the mixer, because that is where a channel/operator routing regression would actually surface.

## jt6295 (OKI M6295) - no upstream bench in the copy

`rtl/sound/jt6295/` is jotego's `hdl/` at `7d76b0be`, via `Arcade-Fuuki_MiSTer`. The copy carries
no `ver/` directory: there is nothing to run. The sibling cores' `sim/oki_tb` plays a sample phrase
through the chip and checks the decoded output; Phase 4 ports it if the sample path is modified.
Vendoring alone does not touch behaviour, so there is no regression to establish yet.

---

## SDRAM controller and stack - no carried unit bench; hardware-proven

`rtl/memory/` and `rtl/memory/sdram/` are the Fuuki stack copied through Seta, unmodified. The
burst-4 read extension was proved on real DE10-nano hardware in `Arcade-Psikyo_MiSTer` against a
command-decoding chip model; the sibling trees do not carry that bench alongside the controller,
and re-deriving it here would test a copy, not the code.

Phase 0 instead drives this stack from the five-CPU harness behind a behavioural SDRAM model in
`rtl/synth_check/`, which is the integration the CPUs actually see. The controller's own timing is
not re-litigated.

## `crt_adjust.sv` - bench not portable; proved by frame comparison

Seta's `sim/seta_crt_tb` found the signed-offset bug this copy carries the fix for, but it needs
Seta's `seta_crt.sv`, `seta_video_timing.sv` and palette models, which are not part of this core.
Porting the bench would prove Seta's glue, not this core's. Phase 2 compares rendered frames
against MAME instead (`docs/WORKFLOW.md`, video comparison), which catches a mis-driven offset
directly.

## `screen_rotate_two.sv` - unchanged MiSTer-devel code

Byte-identical in all 15 sibling cores, no bench anywhere in the family, exercises the DDR3 path.
Proved on hardware in those cores; this core changes nothing.

## `hiscore.v` - no unit bench

Upstream has no bench. Its risk is synthesis inference, not function (Quartus builds the tables
from registers if the read-during-write shape is wrong), and the `[GX]` changes exist because that
already happened at 105 % fit. The Phase 2 fit report is the check. It is excluded from ModelSim
compilation because `ram_addr` is used before its declaration (`vlog-2730/2388`); Quartus accepts
it, and it is vendored, so it is not patched.

## `jtframe_dual_ram16.v` - no bench in the copy

Upstream's jtframe benches are not part of it. It is proved where it is used: the line-buffer and
line-cache benches in `rtl/synth_check/` set the latch parameters the design selects and check
read-during-write.

## `fx68k` - measured, then traced

No upstream bench is carried. It was measured for area and Fmax in `rtl/synth_check/fx68k/`
(`docs/ROADMAP.md`, area budget), and Phase 0's boot trace compares its bus cycles against MAME's
on the same program: `sim/cischeat_boot_tb` boots cischeat's main CPU through `rtl/cpu/fx68k_bus.sv`
against MAME's decoded program image and matches 700,000 consecutive accesses - 70,003 writes and
69,998 replayed I/O reads, in order (`docs/PHASE0.md` §2). That trace is this core's regression for
FX68K, and it is re-run in Phase 2 with the real SDRAM transport in front of it.
